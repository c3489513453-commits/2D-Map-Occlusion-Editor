# 资源可走分界线与最终行走区域设计

日期：2026-09-24

## 目标

在现有地图资源蒙版、遮挡底线和手绘行走图层之上，增加每个资源独立的“可走分界线”。系统自动将资源蒙版中分界线以上的部分加入最终可行走区域，将分界线以下的部分视为障碍物，从而减少手工绘制道路的工作量，并允许人物在资源上半部分行走时产生正确的前后遮挡。

成功标准：

- 用户只需绘制资源蒙版之外的空白道路。
- 手绘道路不能写入任何资源蒙版。
- 每个资源可以自动生成并手工调整可走分界线。
- 调整资源分界线后，无需重新绘制基础道路。
- 自动生成功能只补充尚未画线的资源，绝不覆盖精调内容。
- 导出的单一逻辑包包含完整地图、遮挡图层、最终行走蒙版和可解析 JSON。

## 核心模型

系统维护三类彼此独立的数据：

1. `occlusion_lines`：现有遮挡底线，决定人物何时被资源原图遮挡。
2. `walkable_boundary_lines`：新增的资源可走分界线，决定资源蒙版内部哪些像素可行走。
3. `walkable_layers`：用户手绘的基础道路，只用于资源蒙版之外的空白地面。

每个资源图层的 `walkable_boundary_lines` 使用与遮挡底线相同的折线坐标格式：一条线由若干 `[x, y]` 节点组成。第一版每个资源只使用一条有效可走分界线；数据结构仍保存为线数组，以便沿用现有折线编辑组件并为后续扩展保留空间。

尚未拥有可走分界线的资源，其整个蒙版暂时视为不可行走。这是安全默认值，避免人物穿过尚未配置的障碍物。

## 最终行走判定

定义：

- `R`：所有手绘行走图层的并集。
- `M`：所有资源蒙版的并集。
- `Pᵢ`：第 `i` 个资源蒙版中，位于该资源可走分界线以上的像素。
- `Bᵢ`：第 `i` 个资源蒙版中，位于该资源可走分界线以下的障碍像素；没有分界线时，整个资源蒙版属于 `Bᵢ`。

最终可行走区域为：

```text
Candidates = (R - M) ∪ P₁ ∪ P₂ ∪ ... ∪ Pₙ
FinalWalkable = Candidates - (B₁ ∪ B₂ ∪ ... ∪ Bₙ)
```

含义：

- 用户画出的道路与资源蒙版重叠时，重叠像素会被自动裁掉。
- 资源蒙版内部只由该资源自己的可走分界线决定可行走部分。
- 调整资源分界线会立即改变资源贡献的可走像素，不会修改手绘道路原始数据。
- 多个资源蒙版互相重叠时，任意资源将某像素判定为障碍，该像素都不能行走；障碍优先于其他资源贡献的可走区域。

人物移动继续使用现有脚底接触范围判断：脚底采样点全部位于最终可行走区域时，人物才可以移动到候选位置。

## 分界线上下区域

画布坐标原点位于左上角，Y 轴向下增加。

- 对折线覆盖的每个 X 坐标，通过相邻节点线性插值得到边界 Y。
- 资源蒙版中 `y < boundaryY` 的像素属于线上可走部分。
- `y >= boundaryY` 的像素属于线下障碍部分。
- 折线水平范围之外的资源像素默认视为障碍，避免一条过短的线意外放开资源两侧。
- 最终结果始终与该资源自身蒙版相交，不会把资源外部像素加入可走区域。

## 自动生成

顶部工具栏增加“自动可走”按钮。

对每个具有有效蒙版、但尚无 `walkable_boundary_lines` 的资源：

1. 读取该资源蒙版的非透明边界框。
2. 计算 `boundaryY = top + height × 0.70`，即默认把底部约 30% 设为障碍。
3. 在该资源蒙版边界框的左、右边界之间生成水平折线。
4. 保存为该资源的初始可走分界线。

已经有可走分界线的资源全部跳过，包括自动生成后被用户调整过的资源。按钮结果提示本次新增数量和跳过数量。

现有“自动底线”同样保持增量规则：只处理尚无遮挡底线的资源，不覆盖任何已有内容。

## 编辑交互

### 资源图层

每行资源图层增加“编辑可走”按钮：

- 点击后进入该资源的可走分界线编辑状态，文字变为“退出编辑”。
- 再次点击退出。
- 点击节点并拖动可调整节点。
- 点击线段可选中整条线，按 Delete 删除。
- 画布底部提供“画可走线”工具；左键逐点添加，右键完成。
- 可走分界线使用与遮挡底线明显不同的颜色，并只在普通编辑状态显示；预览模式隐藏。
- 同一时间只能编辑一种空间数据：资源蒙版、遮挡底线、可走分界线或行走图层。

### 行走图层

- 行走图层颜色从绿色改为紫色。
- 点击行走图层的“编辑”后按钮变为“退出编辑”；再次点击结束编辑。
- 画笔、套索和识别工具仍然写入手绘基础道路。
- 每次本地预览和服务端保存都用资源蒙版并集裁剪笔迹，确保基础道路无法写入资源蒙版。
- 擦除工具只修改手绘基础道路，不修改资源分界线产生的自动可走区域。

## 画布显示

普通编辑模式按以下顺序显示辅助信息：

1. 资源蒙版：蓝色。
2. 行走图层：紫色。
3. 遮挡底线：现有橙色。
4. 资源可走分界线：采用独立的高对比颜色。

资源分界线以上的自动可走贡献可使用淡紫色预览，但必须和手绘行走层保持可区分；进入预览模式后所有辅助颜色和线条隐藏，只显示地图、人物及实际遮挡效果。

## API 与持久化

资源图层数据增加：

```json
{
  "walkable_boundary_lines": [
    [[100, 240], [180, 238], [260, 245]]
  ]
}
```

新增接口遵循现有遮挡底线接口风格：

- `PUT /api/maps/{map_id}/layers/{layer_id}/walkable-boundary-lines`
- `POST /api/maps/{map_id}/walkable-boundary-lines/auto`

行走图层的绘制、套索和识别提交在服务端统一执行 `paintedMask AND NOT resourceMaskUnion`。前端也执行同样裁剪以保证即时显示正确，服务端结果是最终权威数据。

旧项目缺少该字段时按空数组读取，不影响已有遮挡底线、蒙版和行走道路。

## 导出格式

勾选“导出遮挡与行走配置 JSON”时仍只产生一套逻辑包：

```text
地图名/
├─ map.png
├─ walkable.png
├─ occlusion.json
└─ occluders/
   └─ 各参与遮挡或资源内行走判定的资源.png
```

`walkable.png` 是 `FinalWalkable` 的原图尺寸黑白蒙版，可直接用于运行时碰撞判断。

`occlusion.json` 保留兼容字段，并为每个资源增加可走分界线。具有遮挡底线或可走分界线的资源都必须出现在 `occluders` 中：

```json
{
  "version": 3,
  "map": {
    "image": "map.png",
    "width": 1254,
    "height": 1254,
    "coordinateOrigin": "top-left"
  },
  "walkableMask": "walkable.png",
  "walkable": {
    "mask": "walkable.png",
    "rule": "character_footprint_must_be_inside",
    "composition": "manual_outside_resources_union_resource_above_boundary"
  },
  "occluders": [
    {
      "id": "resource-id",
      "name": "木桶",
      "image": "occluders/木桶.png",
      "lines": [],
      "walkableBoundaryLines": []
    }
  ]
}
```

运行时只需读取 `walkable.png` 完成移动限制；JSON 中保留分界线用于调试、可视化和未来重新计算。

## 错误处理与数据保护

- 自动生成绝不覆盖非空分界线。
- 删除分界线只删除线数据，不删除资源蒙版。
- 编辑行走道路不会修改资源蒙版。
- 生成最终行走区域时，如果某个资源蒙版丢失，则记录导出失败，不静默放行该区域。
- 保存和重启后，资源分界线、手绘道路及已有遮挡底线均从项目文件恢复。

## 测试范围

- 自动线位于资源边界框高度的 70%，并跳过已有线资源。
- 曲线插值正确区分线上与线下区域。
- 手绘道路提交后不包含任何资源蒙版像素。
- 最终行走蒙版等于基础道路裁剪结果与资源线上区域的组合，且重叠资源的障碍优先。
- 调整资源线后，基础道路数据不改变，最终结果随之改变。
- 行走图层显示为紫色，编辑按钮能切换为“退出编辑”。
- 节点拖动、线段选择、Delete 删除和右键完成画线可用。
- 自动底线和自动可走均只补充缺失项。
- 旧项目可以无损加载。
- 导出包没有重复素材，并包含版本 3 JSON 与最终 `walkable.png`。

## 不在本次范围

- 多层高度、楼层或桥上桥下的复杂导航。
- 自动识别真实三维深度。
- 寻路算法和角色路径规划。
- 为不同角色配置不同碰撞半径。
